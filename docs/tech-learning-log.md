### 2026-06-23｜コスト構造
- **状況・質問**:サイト運営で何にお金がかかるか。サブドメインなら複数サイトでもドメイン1本でよいか。
- **回答サマリ**:必須出費は**独自ドメイン 年約1,500〜2,000円の1本だけ**。ホスティング・開発・計測・AdSense申請は無料。技術的には1ドメイン+サブドメイン/サブディレクトリで複数サイト可だが、SEO観点では下記の通りテーマで分ける判断が要る。
- **関連**:GLOSSARY(商用利用/ドメイン/サブドメイン)、`docs/web-development-rules.md`。

### 2026-06-23｜1ドメインに複数テーマを束ねる是非
- **状況・質問**:人事×システムの専門性で複数領域(退職/個人事業主/PC選び)を1ドメインでよいか。無関係に同居できるか。
- **回答サマリ**:束ねる軸は①テーマ ②人物ブランド ③オーディエンス。**読者(会社員→独立する人)で束ねれば1ドメインで筋が通る**(=オーディエンス軸)。ただし**1ドメインに入れるなら必ず内部リンクで関連づける**(無関係な同居は最悪手)。畑違いの新事業だけ別ドメイン。
- **関連**:GLOSSARY(トピックオーソリティ/内部リンク/サイトを束ねる3つの軸)、ROADMAP §0。

### 2026-06-23｜WordPress vs Next.js
- **状況・質問**:コンテンツはWordPressと一から(Next.js)どちらがよいか、何が違うか。
- **回答サマリ**:本サイト(記事+計算ツール+低コスト+学習)では **Next.js が最適**。WordPressは有料サーバ(PHP/MySQL)が要り年1万円超になりがち・学習が管理画面寄り・中核ツールは結局カスタム。Next.jsは無料ホスティング+記事もツールも一つの土台+Web技術を学べる。
- **関連**:GLOSSARY(CMS/WordPress/Next.js/ヘッドレスCMS)。

### 2026-06-23｜レンダリング方式の使い分け
- **状況・質問**:SSG/ISR/SSR/CSR の違い。ISR・SSRが適切なサイトは?
- **回答サマリ**:SSG=作り置き(記事向き・本サイトの記事)。ISR=全員同じ×定期更新×大量ページ(ニュース/大規模EC/ランキング)。SSR=人ごとに違う/秒単位で最新(ログイン後/検索結果/在庫)。CSR=非公開・インタラクティブ(本サイトの中核ツール)。本サイトは当面SSG中心、SSRは登場しない見込み。
- **関連**:GLOSSARY(SSG/ISR/SSR/CSR)。

### 2026-06-23｜記事の書き方
- **状況・質問**:情報の羅列ではなく「いいポイント」を明確にしたい。AIっぽい長い前置きを直したい。他に効くコツは?
- **回答サマリ**:①記事ごとに**1つのコアメッセージ**を据え、事実は根拠に。②導入は**BLUF(結論先出し)**・咳払いフレーズ排除。③拾い読み構成(見出し/箇条書き/表)。④加えて、検索意図充足・構造化データ・著者性/鮮度・内部リンク質・CWV・CTA・KW自然・a11y・表記統一・YMYL差別化。すべて `docs/article-style-guide.md` に反映済み。
- **関連**:`sites/self/docs/article-style-guide.md`。

### 2026-06-23｜記事生成のエージェント設計
- **状況・質問**:調査と執筆でエージェントを分ける想定。適切な設計は?
- **回答サマリ**:**調査(Sonnet)→執筆(Opus)→校閲(Opus)** の3本。企画(コアメッセージ決め)は人主導。校閲は指摘のみ、修正はオーケストレーター(Claude)が反映+再発は各エージェントに反映(育成ループ)。**多列の表は機械が崩しやすく、人/Claudeの突き合わせ必須**(試運転で実証)。
- **関連**:`.claude/agents/article-*.md`、ROADMAP「記事生成パイプライン」。

### 2026-06-23｜サブエージェントの探索場所(Claude Code)
- **状況・質問**:40_webで開く前提だと、`sites/self/.claude/agents/` のサブエージェントは使えない?
- **回答サマリ**:Claude Code は**起動プロジェクト直下の `.claude/agents/` と `~/.claude/agents/` のみ**を自動認識。サブフォルダは走査されない。→ 記事エージェントは **`40_web/.claude/agents/`** に配置(内部パスは `sites/self/...` 基準)。新セッションから `subagent_type` として認識。
- **関連**:`40_web/.claude/agents/`。

### 2026-06-23｜Claude Design の使い方とデザインの当て方
- **状況・質問**:デザインはClaude Designに依頼すべきか、いつ、確認はどのタイミングか。
- **回答サマリ**:Claude Design は**HTMLで設計→render_preview→確認**するツール。出力はそのままNext.jsにならず、**emile(Claude)がコンポーネント+CSSへ翻訳**(2段)。タイミングは「中核ツール+記事1本」が揃った後(=本サイトは今)。**確認は2ゲート**:①デザイン案ができた時 ②実サイトに実装した時。背景は凝らずプレーンが可読性◎、世界観は配色+数か所の緑+余白で出す。
- **関連**:`sites/self/docs/claude-design-prompt.md`、Claude Designプロジェクト(半歩先から)。

### 2026-06-23｜日本語Webのフォント・改行
- **状況・質問**:フォントが読みにくく文字化けする。改行位置が不自然。
- **回答サマリ**:**Noto Sans JP**(+システムフォントfallback)に統一し、化けやすい特殊記号は使わない。日本語の不自然な途中改行は **`word-break: auto-phrase`(文節改行)** を見出し等に適用して解消。
- **関連**:Claude Design `styles.css`。

### 2026-06-23｜トップページの再利用性(テーマ展開時)
- **状況・質問**:今は退職中心だが将来テーマ展開する。トップは作り直しになる?
- **回答サマリ**:**作り直し不要**。トップは「会社員から独立する人」を看板にし、**ハブ枠を5つ最初から用意**(退職=公開/他=準備中)。展開時は準備中を公開に切り替え+索引/記事一覧に追加するだけ。発生するのは**ヒーロー一文のコピー調整**程度で構造は不変。
- **関連**:Claude Design `home.dc.html`。

### 2026-06-25｜別PCでの作業(git pull/push・複数リポジトリ)
- **状況・質問**:本PJを別PCでも作業したい。開始時に都度 git pull すれば問題ないか。
- **回答サマリ**:基本はそれでOK。ただし前提が3つ。①**pull は push 済みのものしか受け取れない**ので「作業PCで commit & push を溜めない」がセット(=CLAUDE.mdの終了時ルールそのもの)。②本PJは**リポジトリが複数**(管理40_web は `sites/` を gitignore、本体 sites/self、受託 sites/clients は各々別リポジトリ)→ **使う全リポジトリを pull** する必要。40_web だけ pull してもサイト本体は更新されない。③新PCの**初回は clone**(2回目以降が pull)。④`.env`・`node_modules`・ビルド成果物は**git に乗らない**→ 新PCでは `.env` 設置+`npm install` が必要。手順表:初回=各repo clone→.env→npm install / 2回目以降=各repo pull / 毎終了=commit & push。
- **関連**:CLAUDE.md「環境・Git」「セッション運用」、GLOSSARY(clone/pull/push は未登録=必要なら追記)。
